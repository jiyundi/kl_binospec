### 数据和管线结论

- 本地数据根目录：`D:/_RschArchives/RSCH3/UAO-S156-23B-A383/`。
- 本地 Wiki：`D:/_RschArchives/RSCH3/Binospec_Data_Reduction_Pipeline/Home.MD`；同目录包含 `pipeline/bino_fluxcal.pro` 等源码。
- `obj_counts_err_slits_lin.fits` 与 `obj_abs_err_slits_lin.fits` 的 142 个光谱扩展全部数据不同，但核查的 TARGET 112 头信息相同。两者 BUNIT 均为 `1E-17 erg/cm^2/s/Angstrom`。
- `bino_fluxcal.pro` 无条件写入此 BUNIT，即 counts 产品的该字段不足以说明实际单位。Wiki 说明 counts 为 total counts；源码 counts 模式曝光时间约掉，并非每秒计数。是否严格为电子数还需核查上游增益处理。
- 本地源码 counts 误差公式：`err = sqrt(max(I_pipeline + 16, 1))`，读出噪声设为 4。err 是标准差，err² 是候选总方差；`I_pipeline = err² - 16` 仅在非下限像素可逆，是公式推算值，不是独立原始计数测量。
- 本地源码版本与实际历史处理版本是否完全一致，未最终确认。
- TARGET 112 对应 `SLITTARG=100417`、B 视场 `SLITID=39`；用户确认仪器双视场分别编号，TARGET 是合并排序，并无目标错配。
- Set A：`psf_m1/231023`、`psf_m1/231218`、`psf_m1/240115` 三份光谱等权平均；Set C：`psf/231019`；Set B：`psf_p1/231019`。独立观测平均的方差为 `sum(err_j²)/9`。
- split 文件 FLUX 与相应 counts 图逐像素吻合，允许 split 导出时将小于 −200 的数截为 −200。split 波长首像素与 counts WCS 曾见一个像素差异，尚未解决。

### 本会话实施时的接口决定

- `read_spec2d(..., with_variance=True)` 从 split 文件读取 FLUX/LAMBDA；按目标编号找到 counts 扩展，核对像素，再核对 counts/err 坐标头，读取 err² 为 `var_total`。
- 缺失文件、对应不符直接报错；误差非有限或 `err <= 1` 标为无效。`stack_mean_variance` 传播等权平均方差，缺少某份输入的行无效。
- 总方差随所有数组一起翻转、粗裁、重放裁切；源哈希只依赖 flux/wave，因此原方案仍可验证。
- **本会话原实现为了兼容下游 `data + var`，令 `var = var_total - data`；另存 `SpecData.var_total`。** 此时 var 是有效加性项，不是独立高斯背景估计，可为负。
- `reestimate_variance.py` 是独立 pkl 后处理工具，main 不调用；只更新方差、相关 mask 和成像方差，不重裁切、不重新拟合或扣连续谱。新文件用 var_total；旧文件仍用外围散布的 build_var；不读原始 FITS，不能单独把旧文件升级为管线方差。
- 当时未覆盖现有科学 pkl，也未运行完整交互 main 来重写产品。
